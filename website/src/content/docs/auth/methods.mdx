학번과 비밀번호로 포털에 로그인하는 작업의 목록입니다. 세 언어가 같은 기능과 같은 결과를 가지고, 이름 표기만 다릅니다.

## 메서드 대응표

| 작업 | Java | Python | Node.js |
|---|---|---|---|
| 통합: 학생 정보 + 고전독서 + 연락처 | `authenticate(id, pw)` | `authenticate(id, pw)` | `authenticate(id, pw)` |
| DHC: 학생 정보 + 고전독서 | `authenticateWithDHC(id, pw)` | `authenticate_dhc(id, pw)` | `authenticateDhc(id, pw)` |
| SIS: 학생 정보 + 연락처 | `authenticateWithSIS(id, pw)` | `authenticate_sis(id, pw)` | `authenticateSis(id, pw)` |
| SIS 학사 업무 기간 (로그인 필요) | `fetchSisBusinessPeriods(id, pw, year, month)` | `fetch_sis_business_periods(id, pw, year, month="")` | `fetchSisBusinessPeriods(id, pw, { year, month })` |
| 원문 포함 (디버깅) | `authenticateWithRaw`, `authenticateWithDHCRaw`, `authenticateWithSISRaw` | `include_raw=True` | `{ includeRaw: true }` |
| 나머지 SIS 필드 포함 | `authenticate(id, pw, false, true)` | `include_extra=True` | `{ includeExtra: true }` |

- Java는 Spring Boot 자동 설정이 등록하는 `SuhSejongAuthEngine` 빈의 메서드입니다. Spring 없이 쓰는 방법은 [설정](../configuration/)을 보세요.
- Python은 모듈 함수(`from sejongpeia import authenticate`)가 기본 설정의 클라이언트를 쓰고, 설정을 바꾸려면 `SejongAuthClient`를 직접 만듭니다.
- Node.js는 모든 메서드가 `Promise`를 돌려줍니다. Python과 Java는 동기 호출입니다.
- 원문 옵션과 extra 옵션은 [원문·extra 옵션](../raw-and-extra/)에, 결과 필드는 [결과 필드](../result-fields/)에 있습니다.

## 무엇을 보장하나

| 메서드 | 반드시 채워지는 것 | 실패하면 |
|---|---|---|
| 통합 | DHC가 주는 학생 정보와 고전독서 | DHC 단계가 실패하면 호출 전체가 실패합니다 |
| 통합 (연락처 등) | SIS가 주는 이메일, 전화번호, 영문 이름, 학교 코드 | SIS 단계가 실패해도 호출은 성공하고 그 필드만 `null`입니다 |
| 통합 (상위 소속) | 포털 메인 화면의 `parentUnitName` | 포털 메인 단계가 실패해도 호출은 성공하고 `null`입니다 |
| DHC | 학생 정보, 고전독서 | 실패하면 예외 |
| SIS | 학생 정보, 연락처, 학교 코드 (`grade`, `status`는 항상 빈 문자열) | 실패하면 예외 |
| 학사 업무 기간 | 업무별 허용 기간 목록 | 실패하면 재시도 없이 예외 |

- 통합 인증은 포털에 **한 번만** 로그인하고 같은 세션으로 DHC, SIS, 포털 메인을 조회합니다. 학생 정보와 연락처를 따로 부르면 로그인이 두 번 일어나므로 통합 호출 하나를 쓰세요.
- 빈 학번이나 빈 비밀번호는 네트워크 호출 전에 `INVALID_INPUT`으로 거절합니다.
- 틀린 비밀번호는 재시도하지 않고 첫 실패에서 멈춥니다. 이유는 [로그인 판정과 계정 잠금 방지](../../understand/login-verdict/)에 있습니다.
