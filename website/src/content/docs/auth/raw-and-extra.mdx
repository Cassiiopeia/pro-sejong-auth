기본 결과는 이름이 붙은 필드뿐입니다. 아래 두 옵션은 필요할 때만 켭니다. 둘 다 기본은 꺼짐이고, 켜도 다른 필드는 바뀌지 않습니다.

## 원문 옵션

학교가 보낸 응답을 그대로 결과에 담습니다. 디버깅과 파서 점검용입니다.

- 통합 결과: DHC 페이지가 `rawHtml`, SIS `initUserInfo` 응답이 `rawJson`에 들어갑니다. SIS가 실패했으면 `rawJson`은 null입니다.
- DHC 결과는 `rawHtml`, SIS 결과는 `rawJson`만 채워집니다.
- **추가 요청은 없습니다.** 이미 받은 응답을 보관할 뿐입니다.

<Tabs syncKey="language">
  <TabItem label="Java">
    ```java
    SejongAuthResult result = sejongAuthEngine.authenticateWithRaw(studentId, password);
    String html = result.getRawHtml();   // DHC 원문
    String json = result.getRawJson();   // SIS 원문 (SIS 실패 시 null)

    sejongAuthEngine.authenticateWithDHCRaw(studentId, password);   // DHC 결과 + rawHtml
    sejongAuthEngine.authenticateWithSISRaw(studentId, password);   // SIS 결과 + rawJson
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    result = authenticate(student_id, password, include_raw=True)
    html, json_text = result.raw_html, result.raw_json

    authenticate_dhc(student_id, password, include_raw=True)   # DHC 결과 + raw_html
    authenticate_sis(student_id, password, include_raw=True)   # SIS 결과 + raw_json
    ```
  </TabItem>
  <TabItem label="Node.js">
    ```javascript
    const result = await authenticate(studentId, password, { includeRaw: true });
    const { rawHtml, rawJson } = result;

    await authenticateDhc(studentId, password, { includeRaw: true });   // DHC 결과 + rawHtml
    await authenticateSis(studentId, password, { includeRaw: true });   // SIS 결과 + rawJson
    ```
  </TabItem>
</Tabs>

<Aside type="danger" title="원문을 외부로 내보내지 마세요">
SIS 원문에는 세션 식별자로 보이는 값, 접속 IP, 접속 시각이 들어 있습니다. 외부 클라이언트에 그대로 내려주지 마세요.
</Aside>

## extra 옵션

이름 붙인 필드 말고 학교가 주는 나머지 SIS 필드를 `{"데이터셋.필드": "값"}` 맵으로 받습니다. 학교가 필드를 더해도 새 릴리스 없이 접근할 수 있게 하는 통로입니다.

- 대상 데이터셋은 `dm_UserInfoSch`, `dm_UserInfoGam`, `dm_UserInfo`의 스칼라 필드입니다.
- 통합 인증과 SIS 인증에서만 쓸 수 있습니다. DHC 결과에는 extra가 없습니다.
- 옵션을 켜지 않으면 `extra`는 null입니다.

<Tabs syncKey="language">
  <TabItem label="Java">
    ```java
    // 인자: 학번, 비밀번호, 원문 포함 여부, extra 포함 여부
    SejongAuthResult result = sejongAuthEngine.authenticate(studentId, password, false, true);
    Map<String, String> extra = result.getExtra();
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    result = authenticate(student_id, password, include_extra=True)
    extra = result.extra   # {"데이터셋.필드": "값"}
    ```
  </TabItem>
  <TabItem label="Node.js">
    ```javascript
    const result = await authenticate(studentId, password, { includeExtra: true });
    const { extra } = result;   // { '데이터셋.필드': '값' }
    ```
  </TabItem>
</Tabs>

### 항상 제외되는 키

`spec/contract.json`의 `extraExcludedKeyPattern`에 걸리는 키(대소문자 무시)는 extra에 들어가지 않습니다.

```text
(PWD|PASS|JUMIN|RRN|RESI|SSN|BANK|ACNT|ACCT|ACCOUNT|ADDR|ZIP|POST|ALIAS|SESS|TOKEN|SECRET|BIRTH|BRTH|VALID|PHONE|TEL|MOBILE|MAIL|LOGIN|RUNNING|(^|_)IP($|_)|_YN$)
```

세션 값, 접속 IP, 비밀번호와 계정 상태 플래그, 주민번호, 계좌, 주소, 직원 이름 계열(`ALIAS`), 전화, 메일, 생년월일 등이 여기에 해당합니다. 다만 **이름 패턴으로 거르는 최선의 필터**입니다. extra를 외부 클라이언트에 그대로 내려주지 말고, 필요한 키만 골라 쓰세요.

## 호환성 보장 범위 밖

원문의 키와 구조, extra의 키와 값은 학교가 바꾸면 달라집니다. 앱의 핵심 로직을 여기에 걸지 마세요. 안정적인 접근은 [결과 필드](../result-fields/)의 이름 붙은 필드로 하세요. 정책은 [API 안정성](../../api-stability/)에 있습니다.
