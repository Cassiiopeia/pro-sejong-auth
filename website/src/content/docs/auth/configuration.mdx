## 재시도의 범위

- 재시도는 **포털 로그인 요청**에만 적용됩니다. 2xx가 아닌 응답과 시간 초과 때 다시 시도합니다.
- 마지막 시도가 시간 초과면 `CONNECTION_TIMEOUT`, 횟수를 모두 쓰면 `CONNECTION_FAILED`입니다.
- 포털이 틀린 비밀번호나 잠금으로 거부한 로그인은 재시도하지 않습니다. 계정을 지키기 위해서입니다.

## 인증서 검증

기본은 켜짐입니다. 끄는 옵션은 있지만 디버깅 용도로만 생각하세요. 끄면 로그인 정보가 가는 연결을 검증하지 않습니다.

## Java: Spring 없이 쓰기

Spring Boot는 선택 의존성이라 일반 Java 프로젝트는 받지 않습니다. 직접 객체를 엮어 쓰세요.

```java
SejongTlsSupport.ensureLegacyCipherEnabled();   // main() 맨 앞, 다른 HTTPS 호출보다 먼저
SejongAuthProperties properties = new SejongAuthProperties();
SuhSejongAuthEngine engine = new SuhSejongAuthEngine(new SejongPortalClient(properties), new SejongStudentInfoParser(),
    new SejongClassicReadingParser(), new SejongSisClient(properties), new SejongSisParser());
SejongAuthResult result = engine.authenticate(studentId, password);
```

<Aside type="caution" title="Java TLS 주의">
포털은 최신 JDK가 막아 둔 암호(`TLS_RSA_WITH_AES_256_CBC_SHA`)만 제공합니다. 라이브러리는 `jdk.tls.disabledAlgorithms`에서 `TLS_RSA_*`를 빼는데, 이 설정은 **JVM 전체**에 적용되고 JVM의 **첫 TLS 연결 전에만** 효과가 있습니다.

- Spring Boot는 시작할 때 자동으로 처리합니다.
- Spring 없이 쓰면 `main()` 맨 앞에서 `SejongTlsSupport.ensureLegacyCipherEnabled()`를 부르세요. 늦게 부르면 `CONNECTION_FAILED`와 그 원인을 알리는 메시지로 실패합니다.
- JVM 전체 변경을 허용할 수 없다면 인증을 별도 프로세스로 분리하세요.
- Python과 Node.js는 자기 연결의 TLS 설정만 바꿉니다.

배경은 [레거시 TLS](../../understand/legacy-tls/)에 있습니다.
</Aside>
