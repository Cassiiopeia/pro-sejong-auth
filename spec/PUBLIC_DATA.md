# Public data (no login): API contract for all three languages

Sources the school serves without login (verified 2026-10-30, details in [REFERENCE_DATA.md](REFERENCE_DATA.md) and [REFERENCE_DATA_SURVEY.md](REFERENCE_DATA_SURVEY.md)). Java, Python and Node expose the same methods and return the same data; tests compare against [fixtures/public_data/expected_public_data.json](fixtures/public_data/expected_public_data.json), generated by `scripts/generate-public-data-fixtures.py` (the reference mapping).

## Client

| Language | Entry point | Naming |
|---|---|---|
| Python | `sejongpeia.SejongPublicData(timeout_seconds=10, cache_ttl_seconds=86400, failure_cache_seconds=60, cache_max_entries=500, ssl_verification=True)` | `snake_case` methods and fields |
| Node | `new SejongPublicData({ timeoutSeconds, cacheTtlSeconds, failureCacheSeconds, cacheMaxEntries, sslVerification })` (exported from the package) | `camelCase` |
| Java | `kr.suhsaechan.sejongpeia.publicdata.SejongPublicData` (Spring bean via auto-configuration, also constructible) | `camelCase`, Lombok models |

The expected JSON uses `snake_case` keys; the Node and Java tests convert names before comparing. Every model also has `extra` (a map of string to string) except the dormitory models and `CafeteriaMenuItem`.

## Request addresses and fixed values

Every address, endpoint file name, request parameter name (in send order), fixed value (`mode`, `cid`, `bbs_id`, ...), default and limit lives in [contract.json](contract.json) under `publicData`, and **only there**. This document does not repeat them: the table below names the contract entry (for example `publicData.calendar`) and describes what each argument becomes. The contract tests of all three languages fail when a constant drifts from the file, and `scripts/probe-public-data.py` reads the same file.

All requests use the library transport (legacy TLS cipher) and its User-Agent. The `happydorm` responses are JSON with a `text/html` content type: always parse the body as JSON.

## Result rules

- Field mapping is exactly the one in `scripts/generate-public-data-fixtures.py`. Missing or null school values become an empty string (never null), numbers become strings, except `views`, `total` (integers) and `latitude`, `longitude` (numbers).
- `extra`: every school field not used above, as a string, skipping null and empty values and the deny list (`CD_ALIAS1..3` with `_ENG`, `regname`, `regid`, `STACK_TRACE`). Names of staff members must never appear in `extra`.
- Dormitory notices: pinned items come from `topList`, regular ones from `list`, `total` from `totalCount[0].cnt`. The author fields (`regname`, `regid`) are not returned.

## Value rules (same in all languages)

- Missing or null optional fields become an empty string (`0` for `views` and `total`, `0.0` for `latitude` and `longitude`). A row is never dropped, and one odd row never fails the whole list.
- Only a missing or non-array **container** is a failure (`data`, `items`, `events`, `root`, `dl_*`). Dormitory notices are the exception: a missing `topList`, `list` or `totalCount` means no results (empty lists, total 0), because a search without matches is not an outage. An empty `root` array (no first row) is a failure for both dormitory sources, because the school always returns one row.
- Scalar school values are converted to text (strings as they are, numbers in plain decimal form, booleans as `true` or `false`). `Term.year` and other mapped fields are always strings.
- A non-scalar value (object or array) inside `extra` becomes a compact JSON string (no spaces).

## Failure isolation and cache

- In-memory cache per method and arguments, `cache_ttl_seconds` default 86400. A fresh cache entry means no request.
- Any connection failure, timeout, non-2xx status, non-JSON body, missing expected key, or a `_SUBMIT_ERROR_` object returns the last cached value (even if expired), or an empty list (empty object for dormitory notices). It never raises for upstream problems and never exposes `STACK_TRACE` or other server internals.
- Only invalid input raises: `curriculum_courses` with a blank department code or course number, and `graduate_calendar` with a malformed site id (`INVALID_INPUT`, no request). `lectures` never raises for its filters.
- Failures are remembered briefly: after a failed fetch with no cached value, the same call returns the empty value without a request for `failure_cache_seconds` (default 60). A stale cached value is still returned on failure.
- The cache holds at most `cache_max_entries` (default 500) entries; when full the oldest entry is evicted. Per-key locks are released with their entries (no unbounded growth, callers may pass user-typed search text).
- Concurrent calls with the same arguments share one request. At most one request per call (`lectures`, `calendar`, `graduate_calendar` and the others are single requests), except `cafeteria_places` (one request per number up to `max_place_id`, 10 by default, one after the other, see its row).
- Tests run on fixtures through an injectable transport and an injectable clock; no school server in unit tests. Live shape checks are done by `scripts/probe-reference-data.py`.

## Cafeteria places

`cafeteria_menu(place_id)` takes the school's own cafeteria number; the library carries no table of them. Checked 2026-10-30:

- **There is no list endpoint.** The cafeteria page (`cafeteria-info.do`) only calls `mode=getMenuList&placeId=<n>`; its script keeps the mapping from a card to numbers in a fixed table (the card "계절밥상" uses number 1, "진관키친" 3, and the card "산들푸드" shows the stalls 4, 5 and 6 together), and the card list itself is page HTML, which the library does not parse. `mode=getPlaceList` and `mode=getCafeteriaList` answer 404. The campus map list (`campus_places`, category `식당`) has its own ids (not the cafeteria numbers) and no link between the two.
- Calling numbers 0 to 12 once each: 1, 3, 4, 5 and 6 returned menus (`place_name`/`building_name`/`location` of the rows tell which cafeteria: 1 군자관 6층, 3 진관홀 B1층, 4 to 6 학생회관 B1층), the others returned an empty list. One cafeteria card of the page (`빅베어레스토랑`) has no menu number at all, so it can never appear in this list.
- `cafeteria_places()` therefore calls numbers 1 to `max_place_id` (default 10) and lists the ones that answer with rows. Limits to know: a cafeteria whose menu is empty on that day (a weekly menu not yet posted, a holiday) is missing until the next refresh (cache `cache_ttl_seconds`, default one day); a cafeteria numbered above `max_place_id` is not found (raise it, at most 50); the fixed-menu stalls (3 to 6) always have rows, the weekly one (1) does not always. An empty `cafeteria_menu` list does not prove an id is invalid, and the library never guesses a name from a number.
- The numbers the school page uses, taken from its script on 2026-10-30: 1 (weekly menu, lunch and dinner), 3, 4, 5, 6 (fixed menus). Ids can change, so ask `cafeteria_places()` instead of storing them.

### `meal_type_id` (`mealTypeId`)

Only the weekly menu (number 1) has dates and meal types: `meal_type_id` `1` with `meal_name` `중식` (lunch) and `2` with `석식` (dinner) (seen 2026-10-30; the school page draws 1 as lunch and 2 as dinner and ignores other values). Fixed-menu rows (numbers 3 to 6) have no date, day or meal type: those fields are null and become empty strings. The library does not translate the number; use `meal_name`, which the school sends.

## Not in scope here

The graduate schools' calendar is also served by the homepage `calendar` with `category_code` `0002` to `0007` (`yyyy-MM-dd` dates, several months at once); `graduate_calendar` is the per-site source with the school's own site names. The instructor's syllabus (`수업계획서`) is not provided: its report form carries the instructor's name and contact lines (see the survey). Login-required sources (the SIS business periods are `fetchSisBusinessPeriods`, see `PORTAL_FLOW.md` step 2d; student record), HTML-only pages, faculty directories (personal data).
